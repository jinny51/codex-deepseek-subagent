# 设计合同

## 产品使命

在不改变 Codex 主任务模型、Provider、登录方式和原生子任务生命周期的前提下，让主 Agent 只在用户当前原始消息明确开启时，可以选择性地把边界明确、文本输入量大、输出容易复核的工作交给一个经济型外部模型 worker。

本项目追求的是用户可控的数据边界，以及父子两端合计后的成本、等待时间和质量改善，不追求尽可能高的委派率。全局安装只表示能力可用，不表示任何会话或后续消息默认开启。

## 长期价值与临时机制

长期价值是“受主 Agent 管理的经济型文本 worker”。当前 Hook 桥只是处理跨 Provider 任务载体兼容问题的临时机制。

上游原生传输一旦能可靠完成同样的 assignment、身份、权限、取消和 callback 语义，桥接机制应被移除，而不是继续扩张。

## 适合委派

- 当前原始用户 prompt 去除前导空白后，以完整首 token `$use-deepseek-subagent` 开头。
- 范围可以写成一个独立 job。
- 主要工作是读取、搜索、枚举、提取、日志或代码分析。
- 原始材料远多于最终结论。
- 父 Agent 能独立复核关键证据。
- 用户已经接受相应外部 Provider 的数据边界。

## 默认不委派

- 没有当前 turn 的显式前缀，或只在句中提及、引用、讨论 Skill 名称。
- 主线架构决策、关键取舍和最终验收。
- 不可逆或高风险修改。
- 需要图像理解的任务。
- 无法形成自洽 assignment、只能依赖整个根会话猜测的任务。
- 未获用户同意发送给外部 Provider 的秘密、隐私或受监管数据。

## 不可破坏的不变量

1. **主任务保持不变。** 不切换主模型、主 Provider 或 ChatGPT 登录，不把 DeepSeek 写成全局默认。
2. **用户逐条开启。** 只有当前原始用户 prompt 去除前导空白后，以精确、完整、以空白分隔的 `$use-deepseek-subagent` 首 token 开头，才能建立一次性 grant。模型生成的 marker、句中提及和附带标点的近似 token 无效。
3. **Grant 最小化。** 一个 grant 最多允许当前 session、turn 和 cwd 的一个目标 child；接受 spawn 时消费，不能跨边界、重试或复制。无 grant 必须在 child 创建前 fail closed。
4. **委派始终可选。** 显式 grant 是必要条件，不是强制派工；没有明确收益或任务不安全时，主 Agent 自己完成或说明不能委派。
5. **父任务承担责任。** worker 只贡献材料；父任务负责范围、验证和最终回答。
6. **一个 child 只接收一个自洽 job。** assignment 应包含目标、范围、排除项、证据要求和停止条件。
7. **保留 Codex 原生生命周期。** spawn、权限、取消、等待和 callback 不能被直接 API、MCP、daemon 或第二个 CLI 替代。
8. **传输失败必须 fail closed。** 不猜任务，不静默重放，不换模型，不继承根历史冒充成功。
9. **正确归属优先于吞吐。** 无法证明授权或任务关联时，不允许多个同 parent-session/cwd/role 的 reservation 并行竞争。
10. **凭据与任务分离。** API key 不得进入 grant、assignment、Hook 状态、聊天、日志或普通配置正文。
11. **只读不是保密边界。** 文件不能修改，不等于内容不会发送给外部 Provider。
12. **用户决定信任。** 插件和安装器不得伪造 Hook trust。
13. **安装可撤销。** 只管理自己创建的 Agent 文件，不覆盖同名第三方配置，不修改个人 `AGENTS.md` 或顶层 Provider。
14. **兼容层可退役。** 原生传输通过真实能力探针后，优先删除桥接状态，而不是永久保留 workaround。

## 明确非目标

- 全局模型切换器。
- 会话级或全局“持续开启 DeepSeek”开关。
- 通用多 Provider 编排平台。
- 独立聊天客户端或第三方 API wrapper。
- 让廉价 worker 自动接管整个仓库修改的执行器。
- 密钥管理、加密存储或 DLP 产品。
- 为提高吞吐而引入常驻队列服务。

## 反向优化检查

以下改动即使更“自动”或更“强大”，也不应接受：

- 自动委派所有任务。
- 从用户句中的 Skill 名称、父 Agent 输出或 assignment 中推断授权。
- 让一次授权生成多个 children，或跨 turn、session、cwd 延续。
- 默认给 worker 写权限。
- 把完整根会话复制给 child。
- 为并发扫描多个无关联 pending 并随机领取。
- 失败后自动 replay 或替换 Provider。
- 自动信任 Hook。
- 为临时兼容层引入 daemon、远程队列或新的返回通道。
- 只比较 child 单价，不测父任务复核成本、延迟和正确率。

## 变更验收问题

每个功能或优化合入前都必须回答：

1. 主任务的模型、Provider 和登录是否完全未变？
2. 没有当前原始 prompt 的精确首 token 时，是否一定在 child 创建前拒绝？
3. Grant 是否只属于当前 session、turn、cwd，并且最多消费一次？
4. assignment 是否唯一地属于预期 child？
5. 并发、失败和恢复是否仍不会串线或重复执行？
6. 是否扩大了对外数据范围或本地明文驻留时间？
7. 是否新增常驻进程、全局配置或高权限能力？
8. 用户是否仍能看见并控制信任、凭据和付费边界？
9. 父任务是否仍负责验证和最终交付？
10. 原生传输可用后，这项机制能否干净删除？
